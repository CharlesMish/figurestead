# Python 0.9.0a6 / web 0.9.0-alpha.7 — preparation candidate

Status: unpublished candidate, prepared from protected main
`7b9482a939da77bfc0d256682707ef03ee02332a` after PRs #60–#64. Independent
exact-artifact review, integration and separate publication authorization are
required. The current published release remains Python a5 / web alpha.6 at
`56faf759a282d428602d0c02027112f6a508e471`.

## Changes since published a5 / alpha.6

- **Opt-in monotone interpolation (PR #60):** Python and browser interpolation
  preserve interval endpoint bounds, including unevenly spaced observations and
  direction changes. This corrects interpolated geometry; it does not change
  authored observations or introduce a default smoothing policy.
- **Current factual descriptions (PR #60):** browser line/scatter descriptions
  report observed ranges and counts, scatter fits reuse their prepared model,
  and strip descriptions reuse prepared group counts/medians. Generated facts,
  authored narrative and source context remain distinct. Accessibility companions
  and SVG descriptions update with the marks. This is structural text parity,
  not a new statistical interpretation or screen-reader-user qualification.
- **Auxiliary Python scene boundary (PR #60):** `compile_terminal_scene()` rejects
  unsupported contracts instead of silently discarding meaningful fields. It
  remains a finite-only auxiliary route, not transport for ordinary Python NaN
  gaps or a promise of full Python/browser renderer equivalence.
- **Shared browser categorical ticks (PR #60):** Canvas and SVG consume measured
  category-label layout. Rotation/abbreviation preserve plot capacity; full
  labels remain available to accessible tables and SVG tick descriptions.
  Insufficient capacity rejects explicitly. Live and standalone font metrics
  can produce different abbreviations; category values/order are unchanged.
- **Python ordinary-line performance (PR #62):** renderer-space candidate culling
  reduces marker-interior protection work while retaining actual marker shapes,
  own-line clipping, full line geometry and authored dash-phase continuity.
  Dense/overlapping geometry can still require substantial work; this is not a
  universal speed guarantee or a change to marker cadence.
- **Complete categorical-matrix decoration containment (PR #63):** title,
  subtitle, rotated ticks, axis/colorbar labels, status legend and source note
  are checked together. Figurestead-created axes reserve measured space;
  caller-owned axes retain their allocation. Native colorbar removal does not
  disable protection for surviving decorations. Impossible capacity raises
  guidance rather than silently exporting off-canvas status evidence.

PR #61 reconciled living publication documentation and Pages status; it did not
add a package capability. PR #64 patched development/release tooling to Node
24.22.1 / npm 11.19.1, Node 22.23.4 / npm 10.9.9 for consumer checks, and Vite
8.2.4. These tooling corrections are included without a runtime dependency or
consumer-floor change.

## Compatibility and limits

Python >=3.10, Matplotlib >=3.7, NumPy >=1.24, Pillow >=10 and browser Node
>=22.22.0 remain the declared floors. Schema 0.4 and renderer API 1 remain
unchanged. Package counters remain independent. npm publication is intended for
`alpha`; `latest` must remain unchanged.

Corrected interpolation, factual prose, abbreviated category ticks and matrix
layout can visibly differ from alpha.6. Auxiliary compilation may now reject
previously accepted but incompletely represented contracts. No new scientific
observations, summary definitions, theme colors or missing-data semantics are
introduced. Browser `spec.note` remains descriptive source context, not a painted
footer. Compact browser layouts can still require larger hosts or shorter labels.

Persistent line-identity qualification remains bounded to S1–S3. Higher-series
fallback remains deterministic but unqualified; non-solid rhythm is authored.
Direct labels retain their existing 2–3-series/layout/text/export limits.
Browser/portable NaN or null line gaps remain unsupported. There is no new
perceptual-uniformity, CVD, print or universal-accessibility qualification.
Oversized matrix text may require a larger figure or explicit margins; a
conservative text-box collision may reject even when rotated glyph ink would not
touch. Shared semantics do not imply pixel-identical rendering.

## Exact-artifact process

Package inputs are committed before building. One wheel, sdist and npm tarball
are built from a disposable archive of that producing commit with recorded
Python/build/setuptools/wheel and Node/npm versions. The retaining commit adds
those exact bytes, strict SHA-256 manifests, Python source-input bindings and the
coordinated source/member inventory at `release/reviews/0.9.0a6-web-alpha.7.json`.
Rebuilt consumer test wheels are disposable and never replace the retained files.

Historical a5/alpha.6 and earlier artifacts, frozen PR #57, source ledgers,
images, site trees and release records remain unchanged. Source checks are
qualified against producing inputs; ordinary CI does not freeze future source to
this ledger. Publication must consume reviewed retained bytes without repacking.

After separate authorization: TestPyPI exact bytes and clean consumers, then
PyPI with the identical verified TestPyPI prerequisite, then npm under `alpha`
with exact tarball/integrity readback and unchanged `latest`, then the coordinated
GitHub prerelease targeting the accepted protected-main preparation merge.
A successful npm publish followed by delayed visibility requires read-only
investigation, never an automatic second publish. Registry trust/environment
settings and version availability must be freshly authenticated at dispatch.
Living installation/status prose and Pages pointers are a separate postpublication
change; retained image provenance must never be relabeled as fresh alpha.7 output.

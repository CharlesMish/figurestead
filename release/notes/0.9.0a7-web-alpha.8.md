## Changes since published a6 / alpha.7

- **Truthful browser numeric and UTC ticks (PR #67):** Canvas and SVG labels
  read back to the numeric tick values, and UTC labels include the date, time
  and `Z` needed to identify the tick instant at millisecond precision.
  Oversized labels reject with an insufficient-numeric-tick-space error instead
  of being abbreviated. Fractional-millisecond UTC coordinates raise
  `RangeError` instead of collapsing to one timestamp. Generated tick
  coordinates are unchanged. A four-millisecond span around a modern epoch can
  still repeat coordinates; formatting does not invent replacements.
- **Literal Python legend labels (PR #68):** Figurestead-authored labels that
  begin with an underscore, including `_control`, `_reference` and literal
  `_nolegend_`, remain eligible for ordinary legends and direct-label fallback.
  This covers authored scatter and strip categories and extension legend
  handles. It does not add persistent slots to those families. Anonymous
  scatter and strip series stay excluded. Caller-owned Matplotlib artists keep
  Matplotlib's underscore rules; `Axes.legend` is not patched.
- **SVG point-series legend glyphs (PR #69):** scatter and strip-summary SVG
  legends draw the series glyph and stroke the resolved edge or series color.
  Line legends keep their line samples. Canvas legends are unchanged. This is
  not a new marker vocabulary.
- **Heatmap profile gridlines (PR #70):** ordinary `heatmap()` turns the axes
  grid off after `style_axes`, which is what `categorical_matrix` already does.
  Profile gridlines no longer cross cell centers. `line()` still draws its
  profile grid. Colormap, normalization, tick locators and the colorbar are
  unchanged. There is no new heatmap parameter and no browser heatmap.

PR #66 reconciled living publication documentation after a6/alpha.7. It did not
add a package capability.

## Compatibility and limits

Python >=3.10, Matplotlib >=3.7, NumPy >=1.24, Pillow >=10 and browser Node
>=22.22.0 remain the declared floors. Schema 0.4 and renderer API 1 remain
unchanged. Package counters remain independent. npm publication is intended for
`alpha`; `latest` must remain unchanged.

Underscore legend labels, a clear heatmap field, SVG point-legend glyphs and
longer numeric or UTC tick labels can visibly differ from a6/alpha.7. Narrow
figures can now reject numeric ticks that previously fit an abbreviated label.
No new scientific observations, summary definitions, theme colors, tick
coordinates or missing-data semantics are introduced. Direct labels retain
their existing 2–3-series/layout/text/export limits. Browser and portable NaN
or null line gaps remain unsupported. There is no new perceptual-uniformity,
CVD, print or universal-accessibility qualification. Shared semantics do not
imply pixel-identical rendering.

## Exact-artifact process

Package inputs are committed before building. One wheel, sdist and npm tarball
are built from a disposable archive of that producing commit with recorded
Python/build/setuptools/wheel and Node/npm versions. The retaining commit adds
those exact bytes, strict SHA-256 manifests, Python source-input bindings and the
coordinated source/member inventory at `release/reviews/0.9.0a7-web-alpha.8.json`.
Rebuilt consumer test wheels are disposable and never replace the retained files.

Historical a6/alpha.7 and earlier artifacts, frozen PR #57, source ledgers,
images, site trees and release records remain unchanged. Source checks are
qualified against producing inputs; ordinary CI does not freeze future source to
this ledger. Publication must consume reviewed retained bytes without repacking.

After separate authorization: TestPyPI exact bytes and clean consumers, then
PyPI with the identical verified TestPyPI prerequisite, then npm under `alpha`
with exact tarball/integrity readback and unchanged `latest`, then the coordinated
GitHub prerelease targeting the accepted protected-main preparation merge.
A successful npm publish followed by delayed visibility requires read-only
investigation, never an automatic second publish. Registry trust/environment
settings and version availability must be freshly authenticated at dispatch.
Living installation/status prose and Pages pointers are a separate postpublication
change; retained image provenance must never be relabeled as fresh alpha.8 output.
